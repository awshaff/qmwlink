# qmwlink

Quantum-consistent stochastic microwave channels with Rydberg atomic receivers.

`qmwlink` is a Python research toolkit that generates every result of a paper on open-air microwave links between
superconducting nodes. It models the channel and the receiver in one Gaussian language and analyzes two services on the
same stochastic link:

- **Classical communication:** Holevo, heterodyne, homodyne and real-receiver capacities, ergodic and outage.
- **Entanglement distribution:** receiver-referred threshold, outage and negativity.

Receivers (ideal measurement, JPA, HEMT/LNA, Rydberg atomic receiver, coherent transducer) are each written as a
phase-insensitive Gaussian channel or an input-referred added noise. The Rydberg receiver also has a physics model
(weak-probe and full Lindblad engines) that derives its sensitivity, bandwidth and linear range from atomic parameters.

## Status

Milestones M0–M7 are complete: all experiments E1–E9 run and the test suite is green. Some results are not yet
quotable; see [Known limitations](#known-limitations).

## Install

Requires Python ≥ 3.11 and [uv](https://docs.astral.sh/uv/).

```
make install      # creates .venv and installs pinned dependencies (editable)
```

## Usage

```
make test         # pytest with coverage (unit + validation + regression)
make lint         # ruff check + ruff format --check + mypy --strict src
make figs         # run all experiments, using the cache
make paper-figs   # force-run E1–E9, export PDF/CSV/LaTeX to results/paper/
make exp ID=E3    # run one experiment (add FORCE=1 to ignore the cache)
make bench        # per-velocity-class cost of both receiver engines
```

The same commands are available through the `qmw` CLI:

```
qmw list
qmw run configs/e3.yaml [--force] [--out DIR]
qmw figs | paper-figs | tables | bench
```

Results are written to `results/` (git-ignored) and cached by the hash of the experiment config and its input files.
A full `make paper-figs` takes about 12.5 minutes; the test suite takes about 4 minutes.

## Experiments

| ID | What it shows | Config |
|---|---|---|
| E1 | Small-scale transmissivity distribution and the effect of the passivity truncation | `configs/e1.yaml` |
| E2 | Comparison of large-scale fading laws (log-gamma vs baselines) | `configs/e2.yaml` |
| E3 | Entanglement outage vs distance at 5, 30, 100 and 300 GHz | `configs/e3.yaml` |
| E4 | Receiver-referred entanglement window vs added noise | `configs/e4.yaml` |
| E5 | Classical ergodic capacity and Rydberg-vs-LNA throughput | `configs/e5.yaml` |
| E6 | Blackbody-radiation crossover map with literature Rydberg receivers | `configs/e6.yaml` |
| E7 | Diversity hardening and required array size | `configs/e7.yaml` |
| E8 | Outage capacity per receiver | `configs/e8.yaml` |
| E9 | Validity region of the Gaussian Rydberg-receiver model | `configs/e9.yaml` |

`configs/` holds one file per experiment plus two shared inputs: `literature_rar.yaml` (published Rydberg receiver
points with sources) and `defaults.yaml` (the sourced parameter table behind the LaTeX export). Every other sourced
input sits inside the experiment config that uses it; the derivations are in TSD §16.

The ITU-derived absorption and weather inputs (TSD §16.1–16.2) are regenerated by `scripts/derive_inputs.py`, which
needs the optional dependency `itur==0.4.0`:

```
uv pip install --python .venv/bin/python -e ".[scripts]"
.venv/bin/python scripts/derive_inputs.py [--yaml]
```

## Layout

```
src/qmwlink/
  constants.py, thermal.py   physical constants, thermal occupation
  gaussian/                  Gaussian states, channels, entanglement measures
  channel/                   small-scale, large-scale, compound channel, link budget, obstacles
  receivers/                 receiver models; rydberg_physics/ holds the weak-probe and Lindblad engines
  services/                  classical, entanglement, crossover, diversity, throughput map
  experiments/               E1–E9, runner, cache, config schema
  numerics/, io/, plotting/  special functions and quadrature, export and LaTeX, figure style
tests/
  unit/, validation/, regression/, tolerances.py
configs/                     experiment configs and sourced literature inputs
scripts/                     derive_inputs.py: regenerates the ITU-derived inputs of TSD §16
docs/                        specifications and reference values
```

## Known limitations

Details are in `QUESTIONS.md`.

- **E9 numbers are not quotable.** The atomic and optical inputs in `configs/e9.yaml` are placeholders until sourced
  values are supplied (Q-17).
- **Bandwidth and received-field conventions are undecided** (Q-20); both affect what E5 and E9 report.
- **E1 and E2 operating points are provisional** (Q-15).
- **E3 takes about 325 s**, above the 5-minute per-figure budget (Q-22).
- **The full Lindblad engine is slow for strong-probe sweeps** (Q-19).

## Conventions

Vacuum variance 1, SI units at interfaces, bits per mode, covariance-matrix ordering (x_A, p_A, x_B, p_B).
Pure Python with NumPy/SciPy only. Tolerances are frozen in `tests/tolerances.py`.
